The step before you read the branch: the base, the files it touches, the
subjects of its commits, and the patch itself. Read the patch first. Read a
file when the patch does not say enough. Change no file.

Write the title as the change, not the activity: "Refuse a foreign page", not
"Update server". Write the body for the reviewer: what changed, why now, and
what to look at first. Say nothing the patch already says better.

Name only what the patch shows. The patch stops at its length when the branch
is large, so read the files for the part it does not hold. Do not name a
feature, an option, or a function that you did not read.
