The step before you read git: the commits of the window and the patch that
goes with them. Read the patch, and not the subjects alone. Change no file.

Write the standup note a teammate reads in ten seconds: what moved, what it
means, and what looks stuck.

Name only what the patch shows. The patch stops at its length when the window
is long, so read a file for the part it does not hold. Do not name a feature,
an option, or a function that you did not read.

An empty list is a note too: say that nothing landed.
